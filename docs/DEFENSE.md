## 1. The Problem Statement

The repository does not carry an explicit problem statement. The following is the defensible statement derived from what the code actually does. **Use this verbatim.**

> **Problem.** Quantum circuit simulators today answer *"what is the output distribution?"* but not *"why?"*. A learner or an early-stage quantum engineer runs a circuit in Qiskit, gets a histogram of bitstrings, and is given no mechanistic account of how amplitude moved through the register, where entanglement was created, which gates were wasted, or whether an alternative circuit is a better implementation of the same computation. Existing tools split into two camps: professional SDKs (Qiskit, Cirq, PennyLane) that are powerful but require you to already understand the physics to interpret their output, and pretty drag-and-drop toys (IBM Composer, Quirk) that show the state but do not reason about it. Neither closes the loop between *building* a circuit, *observing* the physics, and *improving* the circuit.

> **Thesis.** Q-Insight is a browser-based quantum circuit workbench that makes the *reasoning layer* a first-class output of simulation. Every run returns not only counts and the statevector, but a deterministic, gate-by-gate physical explanation (amplitude transitions, per-qubit populations, entanglement detection via von Neumann entropy), a rule-based optimization report, and a head-to-head structural comparison against a second circuit held in a parallel workspace. The explanations are computed from the evolved statevector — not generated by a language model — so they are reproducible, auditable, and cannot hallucinate.

**Why that framing wins both rooms:**
- To the **physicist**: the claim is not "we invented new physics." The claim is "we expose the physics that simulators already compute but throw away, correctly and reproducibly."
- To the **QML co-founder**: the claim is "explanation and circuit-quality analysis is a product surface, and it is deterministic, which means it is cheap, testable, and defensible — unlike an LLM wrapper."

## 3. Architecture

```
Next.js 15 (App Router, React, TypeScript, Zustand, Tailwind, Recharts, Framer Motion)
        │
        │  persistent WebSocket  (single shared socket, module-level singleton,
        │                         FIFO promise queue, exponential backoff 1s→8s)
        ▼
FastAPI  /ws          ← streaming simulation channel
FastAPI  /variational/run  ← REST parameter sweep
        │
        ├─ compiler/gate_compiler.py   SWAP → 3×CNOT decomposition
        ├─ qiskit_aer AerSimulator     1024 shots / statevector save
        └─ analysis/explainer.py       independent statevector re-evolution + analysis
```

### 3.1 Request path (standard run)
1. `expandCircuit()` flattens `COMPONENT` blocks into primitive gates, offsetting qubit indices by the block's anchor qubit; gates are sorted by canvas column.
2. `serializeCircuit()` strips UI-only keys (`id`, `position`, `label`, `category`).
3. Payload `{qubits, gates, compare_to}` is pushed onto the FIFO `pendingRequests` queue and sent over the socket.
4. Backend validates JSON, emits a `status` frame ("Circuit received"), then compiles → simulates → enriches.
5. `enrich_with_analysis()` attaches `explanation`, `comparison`, `suggestions`.
6. The `result` frame shifts the queue head and resolves its promise; round-trip latency is recorded and shown in the status badge.

### 3.2 Two independent simulation engines (a deliberate design choice worth defending)
The **execution engine** (`main.py`) uses Aer with shots. The **analysis engine** (`explainer.py`) *re-evolves the circuit itself* using `qiskit.quantum_info.Statevector.evolve`, gate by gate, exactly and noiselessly.

Defend it this way: *"The analyzer is an independent exact path. Shot-based counts and the exact analytic distribution are computed by different code, so when the narrative says 50.00% and the histogram says 51.2% over 1024 shots, that agreement is a cross-check, not a tautology. It also means explanations remain exact even for circuits whose sampled output is noisy."*

### 3.3 State management
- `useCircuitStore` (Zustand + immer): `activeCircuit` (A|B), `circuits`, `results`, socket status, `isRunning`. Enforces MAX_QUBITS = 6 in the UI, drops gates referencing removed qubits when the register shrinks, validates every preset before load (target/control in range, control ≠ target, finite θ for parametric gates).
- `useVisualizationStore`: `currentStep` (−1 = initial state), cached stepwise result, `isPlaying`, `speedMs`, modal state.
- `useWebSocket`: module-level singleton so `CircuitBuilder`, `AlgorithmSelector` and `VisualizationPanel` share one connection rather than opening three.

## 4. The Physics and Mathematics — And Where It Lives

### 4.1 State evolution
Register initialised to $|\psi_0\rangle = |0\rangle^{\otimes n}$; each gate applies $|\psi_i\rangle = \hat U(G_i)|\psi_{i-1}\rangle$, identity on untouched qubits. Implemented in `explainer.py::_evolve_state` via Qiskit `Statevector.evolve`. Bit convention is Qiskit little-endian: array index bit $k$ is qubit $k$, and displayed bitstrings are printed MSB-first (`format(i, '0nb')`), so `|01⟩` means $q_1{=}0, q_0{=}1$.

**Verified:** H on q0 of a 2-qubit register → `0.707|00> + 0.707|01>`. Correct.

### 4.2 Reduced density matrix and the Bloch vector
For qubit $k$, the partial trace $\rho^{(k)} = \mathrm{Tr}_{\backslash k}(|\psi\rangle\langle\psi|)$ is computed **without materialising the $2^n\times2^n$ density matrix**. `frontend/lib/quantum.ts::getBlochVectors` pairs amplitudes across the bit mask $2^k$:

$$\rho_{00}=\sum|a_0|^2,\quad \rho_{11}=\sum|a_1|^2,\quad \rho_{10}=\sum a_0^{*}a_1$$
$$x = 2\,\mathrm{Re}\,\rho_{10},\qquad y = 2\,\mathrm{Im}\,\rho_{10},\qquad z = \rho_{00}-\rho_{11}$$

This is $O(2^n)$ per qubit rather than $O(4^n)$ — the right answer to "why not just use `partial_trace`?"

Purity $P=\mathrm{Tr}\big((\rho^{(k)})^2\big)=\rho_{00}^2+\rho_{11}^2+2|\rho_{10}|^2=\tfrac{1+r^2}{2}$, with $r=|\vec b|$. `isMixed` is flagged at $P<0.999$. Bloch angles $\theta=\arccos z$, $\phi=\mathrm{atan2}(y,x)$.

**Sanity checks you should be able to recite:** for a Bell pair, each qubit has $\vec b = 0$, $P = 0.5$ — the arrow collapses to the centre of the sphere. That visual *is* the entanglement. For $H$ then $S$ on one qubit, $\vec b = (0,1,0)$ — verified against the code's sign convention.

> ⚠️ `working.md` §1.2 writes $y = 2\,\mathrm{Im}(\rho_{01})$ on one line and $y = i(\rho_{01}-\rho_{10})$ on the next; these differ by a sign. **The code is correct** ($y = 2\,\mathrm{Im}\,\rho_{10} = -2\,\mathrm{Im}\,\rho_{01}$); the documentation line is the typo. Know this before someone finds it.

### 4.3 Entanglement detection via von Neumann entropy
`explainer.py::_entangled_pairs`: for each pair $(A,B)$ trace out everything else, compute
$$S(\rho)= -\mathrm{Tr}(\rho\log_2\rho) = -\sum_i \lambda_i\log_2\lambda_i$$
and flag the pair if $S(\rho^{(A)})>10^{-6}$ **and** $S(\rho^{(B)})>10^{-6}$.

**The physics justification:** for a *pure* joint state, a subsystem has non-zero entropy **iff** it is entangled with the remainder. Since the analyzer evolves unitarily from $|0\rangle^{\otimes n}$ with no noise channel, the joint state is always pure, so the criterion is exact.

**The honest limitation** (say it before they do): this is a *marginal* test, not a bipartite test on the pair. In a GHZ state it flags q0–q1, q0–q2 and q1–q2, even though tracing out the third qubit leaves any pair in a separable mixed state. It correctly detects "this qubit is entangled with the rest of the register"; it does not certify pairwise entanglement. The rigorous fix is the PPT/Peres–Horodecki criterion or concurrence on $\rho^{(AB)}$ — both are ~15 lines given the existing partial-trace machinery.

### 4.4 Bhattacharyya coefficient for output similarity
$$BC(P_A,P_B)=\sum_{x}\sqrt{P_A(x)P_B(x)} \in [0,1]$$
Computed on the *exact* analytic distributions, not the sampled counts. Related to Hellinger distance by $H^2 = 1 - BC$. Chosen over KL divergence because it is symmetric, bounded, and finite on disjoint support (KL diverges).

### 4.5 Comparison score
$$\text{Score} = 0.4\,\frac{1}{1+d} + 0.25\,\frac{1}{1+g} + 0.2\,\frac{1}{1+\rho} + 0.15\,BC$$
with $d$ = estimated depth (per-lane critical path over the compiled gate list), $g$ = compiled gate count, $\rho$ = redundancy penalty (count of non-trivial optimization findings). Higher is better.

### 4.6 Rule-based optimizer (`suggest_optimizations`)
Five rules over the *compiled* gate list:
1. **Identity removal** — flag `I`.
2. **Zero-angle rotation** — flag $R\in\{RX,RY,RZ,CRX,CRY,CRZ\}$ with $\theta \bmod 2\pi \approx 0$ (tolerance $10^{-9}$).
3. **Self-inverse cancellation** — adjacent identical gates on identical operands from $\{H,X,Y,Z,CNOT,CZ,SWAP\}$, since $U^2=I$.
4. **Inverse pairs** — $(S,S^\dagger)$, $(T,T^\dagger)$ adjacent on the same qubit.
5. **Rotation merging** — adjacent same-axis rotations on the same operands merge to $\theta_1+\theta_2$, normalised to $(-\pi,\pi]$; if $\approx 0$, suggest deletion.

Say plainly: *"This is peephole optimization on the compiled instruction list. It is deliberately a strict subset of what a real transpiler does — it never proposes a rewrite it cannot prove is exactly identity-preserving. It is not competing with Qiskit's transpiler; it is an explainable teaching-grade pass whose every suggestion the user can verify by hand."*

### 4.7 Compilation
`gate_compiler.py` currently implements one rule: `SWAP(a,b) → CNOT(a,b), CNOT(b,a), CNOT(a,b)`. Its purpose is to demonstrate the abstract-gate → native-gate boundary and to make depth/gate-count metrics reflect hardware cost rather than diagram convenience. **Consequence to own:** backend metrics and frontend metrics disagree for any circuit containing a SWAP, and optimization findings index compiled gates, not the gates the user drew.

### 4.8 Variational sweep (`/variational/run`)
Ansatz: $R_y(\theta)$ on every qubit, then a CNOT chain $CX(i,i{+}1)$, then measure all. Cost $C(\theta) = 1 - P(|0\rangle^{\otimes n})$. `optimize_variational` sweeps $\theta$ linearly across $[\text{start},\text{stop}]$ over `iterations` points and returns the best point plus the full history. Wired into the UI: any preset in the **Variational Algorithms** category triggers the REST sweep, reloads the workspace with the optimal $\theta$, and re-simulates.

Own the limitation: *"This is a one-parameter grid sweep, not an optimizer. There is no gradient, no parameter-shift rule, no multi-parameter ansatz, and the cost function is ground-state overlap rather than a Hamiltonian expectation value $\langle\psi(\theta)|H|\psi(\theta)\rangle$. It exists to demonstrate the hybrid quantum-classical loop architecture end-to-end, not to do chemistry."*

### 4.9 Measurement semantics — the sharpest physics point in the project
`explainer.py` does **not** collapse the state at an `M` gate. It records $P(0)$ and $P(1)$ for the measured qubit from the current amplitudes and continues evolving coherently.

**This is correct, and here is why:** the canvas enforces (`CircuitBuilder.tsx::canOccupy`) that no gate may be placed to the right of a measurement on the same wire, and the system has no classical feedforward anywhere. Therefore every measurement is terminal, and by the **principle of deferred measurement** the pre-measurement coherent state carries the complete outcome distribution. Analysing the pre-measurement state is exactly right — not an approximation.

This is also why the **teleportation preset is legitimate**: it applies the `CNOT` and `CZ` corrections *before* the measurements rather than conditioning on classical bits. That is the coherent (deferred-measurement) form of teleportation, and it is the standard way to express teleportation in a simulator without classical control. Verified: teleporting the default $|0\rangle$ yields $q_2 = 0$ on every shot while $q_0, q_1$ are uniformly random over 4 outcomes — exactly the textbook signature.

## 6. Known Weaknesses — And Exactly How To Answer Them

Do not hide these. Every one of them has a clean, informed answer, and volunteering them is what separates "student project" from "engineer who knows their system."

### 6.1 🔴 The comparison engine can declare a wrong circuit the winner
`compare_circuits` scores structural complexity only. It computes output similarity but **never gates on it**. Verified: Grover (depth 7, 12 gates) vs. a single identity gate returns **winner = B** with `output_similarity = 0.0`.

Also, because the same $BC$ value is added to both scores, the similarity term contributes **zero discriminating power** — it shifts both sides equally and can never change the winner.

**Answer:** *"You've found the real one. As built, A-vs-B answers 'which circuit is cheaper to run', not 'which is a better implementation of the same computation' — and the similarity term is mathematically inert because it is symmetric. The fix is two lines of logic: gate the comparison on $BC \ge 1-\epsilon$ and return 'not functionally equivalent — comparison invalid' below that threshold, and move similarity out of the additive score into a precondition. The metric itself is sound; the guard is missing."*

### 6.2 🔴 QFT and QPE use `CRZ` where controlled-phase `CP` is required
$CRZ(\theta) = \mathrm{diag}(1,1,e^{-i\theta/2},e^{i\theta/2})$ but the QFT needs $CP(\theta)=\mathrm{diag}(1,1,1,e^{i\theta})$. They differ by $P(\theta/2)$ on the **control** qubit — a relative phase, not a global one, so the transform is genuinely wrong. It is invisible on $|0\ldots0\rangle$ (all phases act trivially), which is why the presets "look fine."

**Verified numerically:** with `CP`, QPE returns the correct counting-register bitstring with probability **1.000**. With `CRZ`, the same circuit smears to 0.427 / 0.427 / 0.073 / 0.073 — which is exactly the smeared distribution the QPE preset produces. This is the root cause, confirmed. Affects `frontend/lib/algorithms.json` (`qft_3q`, `qpe_basic`, `hhl_demo`) and `api/algorithms/qft.py`.

**Answer:** *"Confirmed defect, and I've isolated it. `CRZ` and `CP` differ by a control-side phase $P(\theta/2)$. The fix is to add `CP` to the gate table — one entry in `gates.ts`, one branch in `apply_gate` and `_apply_gate_to_circuit`, and a swap in the three presets. I verified the corrected circuit gives a delta function on the right bitstring."*

### 6.3 🟠 Circuits with no `M` gate display a false 100% on $|0\ldots0\rangle$
Aer returns `{'000': 1024}` when the classical register is never written. The main `Histogram` reads `result.counts` only and never falls back to `statevector`. The QFT preset (which has no measurements) therefore renders as a certainty on $|000\rangle$ — physically meaningless.

**Answer:** *"Display bug, not a physics bug — the statevector is returned correctly in the same payload, and the step-visualization panel renders it correctly. The main histogram just doesn't fall back to it. One `useMemo` change."*

### 6.4 🟠 Step replay across a measurement is not a single quantum trajectory
`simulate_stepwise_circuit` re-simulates each prefix **independently** with `shots=1`. Once a prefix contains an `M`, each prefix collapses independently. Verified on a Bell circuit: in one run, step 3 showed $|00\rangle$ and step 4 showed $|11\rangle$ — a physically impossible trajectory for a single shot.

**Answer:** *"Real issue, and the honest framing is that the step view is only meaningful up to the first measurement. Two fixes: capture the pre-measurement state for `M` steps (consistent with how the explainer already treats measurement), or seed one RNG across prefixes so the branch is consistent. I'd take the first — it matches the deferred-measurement semantics the rest of the analyzer uses."*

### 6.5 🟠 The W-state preset is not a W state
Measured amplitudes: $0.472|000\rangle - 0.471|001\rangle + 0.333|110\rangle + 0.667|111\rangle$. The target is $(|001\rangle+|010\rangle+|100\rangle)/\sqrt3$. The preset uses plain `RY` + `CNOT` where the standard construction needs a **controlled**-$R_y$ (a $\theta = 2\arccos(1/\sqrt3)$ rotation followed by a controlled rotation and CNOTs).

**Answer:** *"Wrong preset data, not a wrong engine — the simulator faithfully reproduced what the JSON asked for. Fixing it needs a controlled-$R_y$; the gate set already has `CRY`, so it's a data fix in `algorithms.json`."*

### 6.6 🟠 Kyber and Dilithium "presets" are not Kyber and Dilithium
They are generic $H$/$R_y$/$R_z$/`CNOT`/`CZ` ansätze labelled after ML-KEM and ML-DSA. Kyber and Dilithium are **classical lattice-based** post-quantum schemes; they have no natural gate-model circuit at all. The same caveat applies more mildly to `hhl_demo`, which is a QPE-shaped sketch rather than HHL (no eigenvalue inversion, no ancilla rotation, no post-selection).

**Answer — do not defend these, reframe them:** *"Those are mislabelled and I'd cut or rename them. Kyber and Dilithium are classical lattice schemes — there is no meaningful circuit to draw. They were placeholders for a 'post-quantum context' section and they don't belong in an algorithm library. That's a five-minute deletion and it makes the library strictly more credible."* Cutting them yourself, before the demo, is the strongest move available.

### 6.7 🟡 Two disagreeing scoring systems
`ComparisonTable.tsx` uses $\text{score} = 0.6d + 0.4g$ (**lower is better**); `explainer.py` uses the reciprocal-weighted score (**higher is better**) on *compiled* gates. They can name different winners in the same UI. Also, frontend `calculateMetrics` counts `circuit.gates.length` (a `COMPONENT` block counts as **one** gate) while computing depth from the *expanded* gate list — internally inconsistent for any circuit using components.

### 6.8 🟡 Scaling ceiling
UI caps at 6 qubits, backend statevector at 8 ($2^8$ amplitudes). Step replay is $O(m)$ independent simulations for $m$ gates, i.e. $O(m^2)$ gate applications. Entanglement detection is $O(n^2)$ partial traces, each $O(4^n)$ via `DensityMatrix`.

**Answer:** *"Statevector simulation is exponential in qubits — that's physics, not engineering, and every dense simulator hits it. My caps are set for interactive latency on a browser round-trip, not because the engine breaks. The genuinely improvable part is the analyzer's $O(n^2)$ full-density-matrix partial traces; the frontend already does the amplitude-pairing trick in $O(2^n)$ per qubit and the backend should use the same routine."*

### 6.9 🟡 No test suite
Zero unit or integration tests in the repository. Given that §5 and §6 of this document were produced by executing the code against known-answer circuits, **the highest-value next commit is turning exactly those checks into a pytest suite**: Bell → {00,11} equally, Grover(2q) → target with $P=1$, Deutsch–Jozsa balanced → non-zero readout, QFT → matches `qiskit.circuit.library.QFT` up to global phase, superdense → decodes all four messages. That is a known-answer regression suite, and it is the single most credible thing you can add before a technical review.

### 6.10 🟡 Production hygiene
`CORSMiddleware(allow_origins=["*"], allow_credentials=True)` — permissive and, with credentials, a combination browsers reject anyway. No auth, no rate limit, and an unbounded WebSocket loop: a large circuit is a trivial CPU denial-of-service. `frontend/.env` is committed (harmless — it points at localhost — but it shouldn't be tracked). `api/Procfile` runs `uvicorn main:app`, which only resolves if the process starts inside `api/`, while the README documents `uvicorn api.main:app` from the root — the dual-import `try/except ModuleNotFoundError` in `main.py` exists precisely to paper over that. Branding is inconsistent across README ("QHack Quantum Lab"), UI ("Quantum Lab"), and repo name ("Q-Insight").

## 7. Anticipated Questions — The Physicist Track

**Q: Which convention are your bitstrings in?**
Qiskit little-endian. Array index bit $k$ ↔ qubit $k$; displayed strings are MSB-first, so in `|01⟩` the right-hand character is $q_0$. Verified: H on q0 of a 2-qubit register gives `0.707|00> + 0.707|01>`, not `|10>`. (Note: the example in `working.md` §6.3 prints `|10>` — that hand-written doc example is wrong; the code is right.)

**Q: You don't collapse the state at a measurement. Isn't that wrong?**
No — see §4.9. All measurements are terminal by construction (the canvas forbids gates to the right of an `M` on the same wire) and there is no classical feedforward, so the principle of deferred measurement makes the pre-measurement coherent state the complete and exact description. If I ever add mid-circuit measurement *with* classical control, this assumption breaks and I would need a genuine collapse-and-branch path.

**Q: How do you know two qubits are entangled?**
Non-zero von Neumann entropy of the reduced state, valid because the joint state is always pure here (unitary evolution from $|0\rangle^{\otimes n}$, no noise channels). Limitation stated up front: it is a marginal test — GHZ flags all three pairs even though each pair alone is separable. Concurrence or PPT on $\rho^{(AB)}$ is the correct pairwise upgrade.

**Q: Why is the Bloch arrow shorter than the sphere for entangled qubits?**
Because the reduced state is mixed. $|\vec b| = r$ and $P = (1+r^2)/2$; a maximally entangled qubit has $r=0$, $P=0.5$, and sits at the origin. That shrinkage *is* the visual signature of entanglement, and the panel labels it via the `isMixed` flag.

**Q: Your QPE doesn't give a clean answer.**
Correct, and I know exactly why — §6.2. `CRZ` instead of `CP`; they differ by $P(\theta/2)$ on the control. I verified that with `CP` the same circuit returns the correct bitstring with probability 1.000, and with `CRZ` it smears to 0.427/0.427/0.073/0.073, which is precisely what the preset shows.

**Q: Is 1024 shots enough?**
For distributions with support on ≤ 8 basis states, standard error is $\sqrt{p(1-p)/1024} \approx 1.6\%$ at $p=0.5$ — visible on the histogram, which is pedagogically useful. And it doesn't affect the explanations, which come from the exact statevector path, not the samples.

**Q: Is there any noise model?**
No — it is a noiseless statevector simulator. That is a deliberate scope choice: the product's job is to make ideal quantum mechanics legible. Aer supports `NoiseModel` natively, so adding depolarizing/amplitude-damping channels is an incremental change — but it would require replacing `Statevector` with `DensityMatrix` throughout the analyzer, which changes the entanglement criterion (entropy no longer implies entanglement once the joint state is mixed).

## 8. Anticipated Questions — The QML Founder Track

**Q: Why not just use Qiskit / PennyLane / IBM Composer?**
Because none of them return a *reasoning object*. Qiskit gives you a histogram. Quirk gives you a live state. Neither tells you "amplitude moved from $|00\rangle$ to $|11\rangle$ here, these two qubits became entangled at gate 2, gates 5 and 6 cancel, and Circuit B does the same thing in 3 fewer gates." That structured explanation payload is the product, and it is a machine-readable JSON contract — it can drive a UI, a grading rubric, or a training signal.

**Q: Is this an LLM wrapper?**
No, and that is the deliberate architectural bet. Every sentence in the explanation is generated by deterministic template composition over quantities computed from the evolved statevector. It cannot hallucinate a physical claim, it runs in ~30 ms with no inference cost, it is unit-testable, and it works offline. If I add an LLM later it goes on top as a rephrasing layer over a verified fact payload — never as the source of the physics.

**Q: Where's the QML?**
Honestly: today there is one variational hook — an $R_y$ + CNOT-chain ansatz with a linear $\theta$ sweep against a ground-state-overlap cost, exposed over REST and wired into the Variational preset category. It proves the hybrid loop architecture end-to-end (frontend → classical optimizer → quantum evaluation → reload → re-simulate). It is not yet an optimizer. The path from here is concrete: multi-parameter ansätze, parameter-shift-rule gradients, Hamiltonian expectation values instead of overlap, and a loss-landscape visualization — which is where the existing step-replay and Bloch machinery becomes genuinely differentiated, because nobody visualizes *why* an ansatz is barren.

**Q: What's the moat?**
Not the simulator — Aer is the simulator and I'd never rebuild it. The asset is the analysis contract: a stable JSON schema pairing every gate with its exact before/after state, an entanglement verdict, a provable-rewrite optimization report, and a comparison score. That schema is reusable as an education product, an interview/assessment grader, and as structured supervision for training models to reason about circuits.

**Q: Who is the user?**
Primary: students and self-taught engineers who can read a circuit diagram but cannot yet read a statevector. Secondary: educators who need a tool that *shows its work*. ## 10. Three Rules For The Room

1. **Volunteer the defects before they're found.** §6.1, §6.2, §6.5 and §6.6 are all findable in ten minutes by someone who knows the field. Naming them first — with the root cause and the fix — converts every one of them from a failure into evidence that you understand your own system.
2. **Separate engine from data.** The W-state, QPE and PQC problems are wrong *JSON presets*. The simulation and analysis engines faithfully reproduced what they were given, and Bell, GHZ, Grover, Deutsch, Deutsch–Jozsa, teleportation and superdense coding are all verifiably exact. That distinction is the difference between "the physics is broken" and "three preset files need editing."
3. **Never overclaim.** Say "concept sketch" for HHL. Say "a parameter sweep, not an optimizer" for the variational module. Say "no noise model." Precision about scope reads as competence; inflation gets punished immediately in a room that contains a physicist.
